# Architecture Suite

Offline, evidence-backed C4 architecture diagrams for coding agents and the command line: system context, containers, components, code, overviews, AWS and Google Cloud deployment diagrams, request scenarios, infrastructure imports, architecture diffs and rule checks, and a read-only HTML explorer. Output is editable Draw.io, Mermaid, PNG and SVG.

## Install in Claude Code

```text
/plugin marketplace add tyler59simon/architecture-suite-plugin#release
/plugin install architecture-suite@architecture-suite
```

The `release` branch holds only the plugin (skills, runtime, license files). Pin a specific version with `#plugin-v1.0.0`.

The skills share one Python runtime. The first time a skill runs, it asks before running the one-time setup:

```text
python <plugin>/skills/architecture-suite-runtime/scripts/bootstrap.py
```

Setup needs network access and Python 3.11-3.14 (if your default `python` is outside that range, bootstrap finds a supported one). It installs hash-pinned dependencies into `~/.architecture-suite/runtime` and downloads Chromium for PNG export (skip it with `--no-browser`). After setup, everything runs offline.

Other agent hosts (Codex, GitHub Copilot, Factory): download the host archive from the [latest release](https://github.com/tyler59simon/architecture-suite-plugin/releases), or install from a checkout with `python tools/install_skill.py --host codex|claude|copilot|factory|all --scope user|project`.

Windows: paths inside the plugin reach about 240 characters at the default cache location. If installation or `doctor` reports missing files and your profile folder name is unusually long, enable long paths (`git config --global core.longpaths true`, and the `LongPathsEnabled` policy) or set `CLAUDE_CODE_PLUGIN_CACHE_DIR` to a short folder.

## Skills

One plugin, nine skills, one shared offline runtime.

| Skill | Purpose |
| --- | --- |
| `c4-diagrams` | Full L1-L4 package plus overview from requirements, documents or chat |
| `reverse-engineer-c4` | Draft, verify and render C4 from an existing repository |
| `c4-system` | Level 1 system context only |
| `c4-container` | Level 2 containers only |
| `c4-component` | Level 3 components (one view per container) |
| `c4-code` | Level 4 code views (one per component) |
| `c4-overview` | Five overview styles and the offline explorer |
| `c4-aws` | AWS deployment diagram and infrastructure import |
| `c4-gcp` | Google Cloud deployment diagram and infrastructure import |

Scenarios, diffs, rule checks and the explorer are CLI commands reachable from these skills (see [extensions](skills/architecture-suite-runtime/references/extensions.md)).

## Command line

```powershell
py -3.13 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-lock.txt
./.venv/Scripts/python.exe -m pip install --no-deps -e .
./.venv/Scripts/python.exe -m playwright install chromium
./.venv/Scripts/architecture-suite.exe doctor
```

On macOS/Linux use `python3.13`, `.venv/bin/python` and `.venv/bin/architecture-suite`. See the [runtime reference](skills/architecture-suite-runtime/references/runtime.md) for every command.

## Trust and data handling

Analysis never executes repository code, never calls cloud APIs and never downloads anything after setup. Repository text is treated as evidence, not instructions. Credential-like values are redacted before evidence is saved, writes are staged and need `--confirm-write`, and bundled assets are verified against SHA-256 manifests. Static analysis produces reviewable candidates; it does not prove deployability, ownership or runtime call graphs.
